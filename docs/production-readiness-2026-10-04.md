Audited homepage, shop, search/filter states, collections, a real product detail, cart, checkout, account entry, order-access denial, About, Contact, confirmation, 404 and admin entry. The browser matrix covered 17 routes/states at 320, 360, 375, 390, 393, 412, 430, 480, 768, 820, 1024, 1280, 1440 and 1920px: 238 cases, plus 28 populated cart/checkout width checks using an actual catalogue variant in browser-local storage; no page exceptions or root horizontal overflow. Mobile menu locks background scrolling, closes on Escape/desktop resize and links to the account page. Signup and reset-request forms were additionally exercised by their actual buttons.

Authenticated dashboard/order/admin screens and a completed password recovery require real test credentials and a recovery email; their browser flows are **not** verified by anonymous route checks. Existing SQL tests independently verify customer/admin authorization.

## 3. Cloud/color changes
Added three medium cloud placements using existing compressed assets and restrained blush/lavender/blue light. Phones use fewer cloud nodes, smaller blur and no ambient drift. No new generated imagery, products, fonts or image replacements.

## 4. Performance
Phones retain native scrolling; Lenis runs only at tablet/desktop widths without reduced motion. Kept existing responsive carousel WebPs and complete homepage photographs. Replaced unbounded review-rating pagination with one RLS-respecting aggregate RPC, retaining the rating distribution. Requests have actual streamed JSON limits; media upload parsing is bounded before decode, including requests without Content-Length. Existing 5MB file, signature/MIME, pixel-count and re-encoding protections remain.

External product photography is still hosted by Google. A direct real catalogue source returned HTTP 200; all four catalogue photographs also loaded with HTTP 200 in Chromium after waiting for the external host. Browser timing is not a guarantee of future external host availability. No Lighthouse score or measured bundle reduction is claimed.

## 5. Security fixes and verified protections
Added safe API error responses, bounded JSON parsing, precise content-type checks, explicit checkout/review authentication, a mandatory commit idempotency key check and bounded review product identifiers. Retained same-origin mutation checks, server-derived ownership, trusted database prices/stock/rewards, strict admin schemas and role guards. Authentication failures no longer expose provider diagnostics; failed sign-out is handled. Added per-response nonce script CSP, nosniff, framing denial, referrer/permissions policies, production HSTS and private no-store for account/admin/API/checkout/confirmation. CSP permits inline styles for existing GSAP/React styling, HTTPS catalogue images and configured Supabase connections; production scripts do not permit unsafe-eval.

Live database audit: all public tables have RLS enabled; both admin views use security_invoker; privileged functions are scoped with fixed search paths and restricted execution grants. Applied the approved-review summary and private per-account quota migrations. Durable quotas protect checkout/reviews inside the public RPCs, plus account writes, admin access and uploads in the server endpoints; fixed thresholds derive identity from auth.uid(), with no caller-selected user or limits. Public publishable keys are intentional. No privileged secret patterns were found in the inspected source, only `.env.example` is tracked, and the current environment contains no private key values to compare against client bundles. This does not certify historical credentials or provider-side secrets.

Authenticated browser recovery, account persistence, admin upload and sign-out remain external test items.
